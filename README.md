1. Процессы и потоки

Процесс — это запущенная программа со своим адресным пространством и ресурсами. Поток — последовательность команд внутри процесса, которой операционная система выделяет процессорное время.

Потоки одного процесса используют общую память и открытые файлы. При этом у каждого потока свой стек, регистры и счётчик команд. Например, один поток приложения может обрабатывать нажатия, пока другой загружает данные.

2. Состояния потока

* Готовность — поток может работать и ждёт, когда ему выделят процессор.
* Выполнение — процессор выполняет команды потока.
* Ожидание — поток ждёт события, например завершения чтения файла.

После завершения чтения поток возвращается в состояние готовности. Если у работающего потока заканчивается выделенное время, он тоже возвращается в очередь готовых.

3. Планирование и диспетчеризация

Планирование определяет, какой из готовых потоков получит процессор и когда произойдёт переключение. Диспетчеризация выполняет это решение. ОС сохраняет регистры текущего потока, восстанавливает регистры выбранного и продолжает его выполнение с прерванного места.

При вытесняющем планировании ОС может остановить текущий поток, например по истечении кванта времени. При невытесняющем планировании поток продолжает работу, пока не завершится, не перейдёт в ожидание или сам не уступит процессор.

4. Основные алгоритмы планирования

* FIFO — задачи выполняются в порядке поступления. Длинная задача может задержать все следующие.
* SJF — первой запускается задача с наименьшим предполагаемым временем выполнения.
* SRTF — выполняется задача с наименьшим оставшимся временем. Новая короткая задача может вытеснить текущую.
* Round Robin — каждому готовому потоку по очереди выделяется квант, то есть ограниченный интервал процессорного времени. При слишком маленьком кванте ОС тратит больше времени на переключения.
* Приоритетное планирование — процессор получает готовый поток с более высоким приоритетом. Если такие потоки поступают постоянно, задачи с низким приоритетом могут ждать очень долго.

В пакетных системах важно быстрее завершать задачи, в интерактивных — быстро реагировать на действия пользователя, а в системах реального времени — укладываться в заданные сроки.

5. Синхронизация и взаимные блокировки

Гонка возникает, когда результат зависит от порядка действий потоков. Например, два потока читают счётчик со значением 0 и оба записывают 1. Одно увеличение теряется, и вместо 2 получается 1.

Участок кода, который работает с общими данными и требует защиты, называется критической секцией. Мьютекс пропускает в неё один поток за раз. Семафор позволяет ограничить число потоков, одновременно использующих ресурс.

Взаимная блокировка, или дедлок, возникает, например, когда первый поток удерживает ресурс A и ждёт B, а второй удерживает B и ждёт A. Один из способов предотвратить такой тупик — обязать все потоки захватывать ресурсы в одинаковом порядке.

6. Обмен данными между процессами

Для обмена данными процессы используют каналы, очереди сообщений, сокеты и разделяемую память. Каналы передают поток байтов, очереди — отдельные сообщения, а сокеты позволяют обмениваться данными и по сети. Разделяемая память даёт процессам доступ к общей области данных, поэтому одновременную запись нужно согласовывать.
